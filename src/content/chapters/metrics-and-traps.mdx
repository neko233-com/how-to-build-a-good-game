第 09 章说清楚了数值的位置：它是描述工具，不是解释工具。但描述本身也有手艺好坏之分——**同样是看数字，有人看出生死，有人只看到安慰**。这一章讲怎么成为前者。

## D1/D7 为什么能预测生死

留存是最老生常谈的指标，但很少有人说清楚**为什么**次日留存和七日留存有预测力。答案在曲线的形状，不在数值的高低。

一个健康的留存曲线是**先陡后缓**的：头几天掉得厉害，随后快速变平，形成一条长尾。它说明两件事：

- **D1 反映第一印象**：玩家是否理解了这个游戏是什么、值不值得再来一次。D1 崩掉，通常是「预期错位」——买量的素材许诺了一个游戏，进去发现是另一个。
- **D7 反映核心循环是否成立**：能撑过一周的玩家，已经把循环跑了好几圈。D7 崩掉而 D1 正常，说明循环本身留不住人——问题在游戏里，不在包装上。

<Callout type="warning" title="曲线形状比单点数值重要">
  一条「数值不高但快速走平」的曲线，好过一条「前高后一直缓慢下滑」的曲线。前者是盘子小但留得住；后者是漏水的桶，再多的新增也只是延缓见底。看单日数值会漏掉这个区别，看整条曲线不会。

</Callout>

## 付费漏斗最容易被误读的一环

从「进入游戏」到「完成付费」的漏斗，每一层都有转化率。其中**最容易误读的是付费率本身**——因为它是一个比率，而比率抹掉了结构。

误读的典型形态：「付费率 8%，比品类平均高，说明商业化做得好。」

问题在于付费率的**分布**。F2P 的付费高度集中在少数用户身上：一个 8% 的付费率，可能来自「8% 的人各付一点」，也可能来自「0.5% 的人付了很多 + 7.5% 的人付了一次首充」。两者是两种完全不同的生意：前者底盘稳，后者极度依赖头部，而头部是会被消耗的。

所以看付费，永远要配两个结构指标一起看：**付费深度分布**（多少人付了多少档位），和**复购率**（付过的人里有多少再付）。只看付费率，等于只看平均数——而平均数正是被头部拉高的那种数。

## 幸存者偏差：成功学方法论的死穴

第 09 章引过那个「人造音乐市场」实验：同一批歌在不同世界里排名天差地别，专家无法预测。它还有一个更直接的推论：**我们看到的成功案例，是从大量尝试里被结果筛选出来的样本。**

用这些样本反推方法论，就是幸存者偏差的标准形态。它的隐蔽之处在于：**每一条单独看都对**。「他们重视留存」「他们每周更新」「他们敢砍功能」——任何成功者身上都能观察到无数个这样的属性，而失败者身上同样有。缺少的不是观察，是**对照**：没看到的那个世界里，做了一模一样事情却死掉的项目。

实用的解毒剂是一个换位问题：**把这条成功经验套到一个失败项目上，它还成立吗**？成立的话，它就没有区分力，不是原因（第 09 章的对称性检验，在这里同样适用）。

## 指标一旦成为目标

这一节是第 09 章的续篇。第 09 章讲「数值是目标的下游」，这里讲它的动态版本——**指标被用于考核的那一刻起，它就开始失真。**

<CompareTable caption="两条以人名命名的定律（都已成了共识，出处见附录 C）">

| 定律          | 内容                                                         | 游戏里的典型形态                                               |
| ------------- | ------------------------------------------------------------ | -------------------------------------------------------------- |
| Goodhart 定律 | 一项统计规律一旦被用于控制目的，它就会失效                   | 次日留存被设为 KPI 后，注册送豪华首日礼包把指标做上去，D7 崩掉 |
| Campbell 定律 | 量化指标一旦用于决策，就越容易被腐蚀，并扭曲它本欲监测的过程 | 在线时长被考核后，设计开始奖励挂机而不是游玩                   |

</CompareTable>

这两条定律冷酷的地方在于：**失真不是因为执行的人坏，而是结构性的**。只要指标和奖惩挂钩，围绕它的优化就一定会发生——包括那些毁掉指标本意的优化。所以成熟的用法是：**指标用于观察，判断用于决策**。把「看什么」和「考什么」分开，是唯一能长期保持指标干净的用法。

## 结果指标与过程指标

最后一个分类工具。混用这两类指标，是日常分析里最常见的低级错误。

<CompareTable caption="两类指标的分界">

|              | 结果指标             | 过程指标                                 |
| ------------ | -------------------- | ---------------------------------------- |
| 回答什么     | 发生了什么           | 正在往那个方向走吗                       |
| 例子         | 流水、留存率、付费率 | 新手引导完成率、首日战斗次数、素材点击率 |
| 能否直接干预 | 不能——它是结果       | 能——它是行为                             |
| 常见误用     | 拿它当每周的行动项   | 拿它证明成功                             |

</CompareTable>

误用的方向通常是前者：周会上对着留存率讨论「我们下周把留存提上去」——留存是结果，不能被直接做。能被做的是那些影响它的行为：引导流程、首日体验、推送时机。**把结果指标翻译成过程指标，再对过程指标行动**，这一步翻译做得好不好，几乎就是数据分析有没有用的分界线。

## 这一章可以带走什么

- 看留存看曲线形状：D1 反映第一印象，D7 反映核心循环；快速走平的长尾好过前高后滑。
- 付费率必须配付费深度分布和复购率一起看，单看比率会被头部骗。
- 成功案例的每条经验都「对」，但套到失败项目上也成立的，就没有区分力。
- Goodhart 与 Campbell：指标和奖惩挂钩的那一刻起就开始失真，这是结构性的。看什么和考什么要分开。
- 把结果指标翻译成过程指标再行动——这步翻译是数据分析有没有用的分界线。
